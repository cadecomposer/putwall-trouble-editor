# Putwall Trouble Spreadsheet Editor

A small web tool that turns an **OC Clearing** export into a Putwall-ready
spreadsheet in a few clicks:

1. **Filter** the report down to the `TRBL-PW-xx` locations you are working.
2. **Sort** by the first `Active Locn` column, Z-A.
3. **Add a `Label` column** to the right of `Tote Gid`, numbering the distinct
   tote numbers top-to-bottom (blanks ignored, repeated totes share a number).
4. **Sort every kept row into a section** (see below):
   - **Troubles** - has an active location. These are the printable ones.
   - **Alt form** - no active location, but a reserve location exists. Send an
     alt form so an EO can grab it.
   - **Split cancel** - no active and no reserve location, and no other item on
     the same order is findable. Safe to split cancel.
   - **Do NOT split cancel yet** - no active/reserve, but another item on the
     **same order** (same `oLPN`) is findable, so hold it until that item is found.
   - **Duplicates** - later copies of an earlier row that share the same
     `oLPN`, `Tote Gid`, `Item`, `Need` and active location.
5. **Generate scannable Code 128 barcodes** for the printable troubles' totes.
6. **Highlight the `Need` cell yellow** when it is more than 1, and the
   `Active OH` cell orange when it is less than 1 (zero or negative).
7. **Preview the barcodes** right in the page.
8. **Download** the edited `.xlsx` (one sheet per section), or **print** the
   troubles table — optionally split across pages for multiple pickers — plus a
   page of barcode labels.
9. **Fill in and print an alt form** for items that only have a reserve
   location, adding the location and case that are not on the export.

Everything runs in the browser. No file, order, item or tote data is ever
uploaded anywhere.

## Quick start

### Option A - just open the single file (no install, no internet)

Open **`dist/putwall-trouble-editor.html`** in Chrome, Edge or Firefox.
It is fully self-contained (all libraries inlined), so it works offline and
does not need the internet or a server. You can copy it to a USB stick, email
it to yourself, or keep it on the work PC.

### Option B - run the source folder (for editing / development)

```bash
cd "putwall trouble spreadsheet editor"
python3 -m http.server 8137
# then open http://localhost:8137/index.html
```

### Option C - rebuild the single file after editing the sources

```bash
python3 build.py        # writes dist/putwall-trouble-editor.html
```

### Run the tests (optional)

```bash
node test/test-processor.js     # runs the logic against a real OC Clearing export
node test/test-sections.js      # checks normal / alt / split / hold / duplicate handling
node test/test-filter.js        # checks that changing locations recalculates everything
node test/test-columns.js       # checks which columns compact mode hides
```

The sections test uses a small synthetic file (`test/sample-sections.xlsx`) that
covers every case. It is generated by `test/make-sample-sections.js` and kept
local (it is a spreadsheet, so it is `.gitignore`d and never published).

## How to use it

1. Tick the `TRBL-PW-01` … `TRBL-PW-20` locations you are working today. You
   can do this before **or after** adding the file. (`Select all 20` and
   `Clear` are there if you need them.)
2. Drag the OC Clearing `.xlsx` onto the box, or click to choose the file. The
   file is always read; if no locations are ticked yet, the page simply waits
   for you to choose some.
3. Read the sections:
   - **Troubles** (with barcodes) is the printable list.
   - **Alt form**, **Split cancel**, **Do NOT split cancel yet** and
     **Duplicates** are the special-handling lists. None of them print.
   - Rows with an `Active OH` below 1 have that cell highlighted orange so a
     stock problem is easy to spot.
4. By default the tables show only the useful columns, from `oLPN` through
   `Reserve Locn` (`OC Mod` and `Reserve Locn 2` are hidden). Click **Show all
   columns** to reveal the rest (`Time in OC`, `Order Date`, `Wave`, `OC Mod`,
   `iLPN`, `iLPN2`, `Reserve Locn 2`, `Staging Locn`), and click again to hide
   them.
5. Click **Print sheet + barcodes** (the highlighted button), or use
   **Print sheet** / **Print barcodes** if you only need one part. **Download
   .xlsx** saves the full workbook.

The locations are a live filter on the imported file. Changing the ticks
re-runs the whole edit from the original spreadsheet immediately, so the alt
forms, split cancels/holds, duplicate marking, tote-number labels and barcodes
are always recalculated for the current selection. Un-ticking every location
hides the results until at least one is ticked again; it does not discard the
imported file.

### Hiding rows

Every section has an eye button on each row. The open eye means the row is
visible; click it to hide the row (the eye becomes crossed out). A hidden row
stays in the table, greyed out and crossed through, but it is skipped when the
Troubles sheet and barcode labels are printed. Hidden alt-form rows are also
left out of the fill-in popup and the printed alt form. Hiding does **not**
re-process anything: tote-number labels and sections stay exactly as they were.
Hidden rows stay hidden while you change the location filter, and are only
cleared by **Start over**.

### Adding a row to the alt form

Troubles rows have a small **+alt** button next to the eye. Use it when the
system says stock exists but you cannot find it: the row is added to the Alt
form section (and to the printed/downloaded alt form), and is automatically
hidden from the Troubles list so it is no longer printed with the troubles or
barcodes. It is still visible in the Alt form section. Click **-alt** on the
same row to undo the addition and put it back on the Troubles list. Rows with
an `Active OH` below 1 are highlighted orange to make those cases easy to find,
but they are **not** added automatically.

The eye button is different: it hides a row everywhere, including the Alt form.
A row moved with **+alt** shows a crossed-out, disabled eye in Troubles until
you click **-alt**.

### Why "Do NOT split cancel yet"?

Anything with the same `oLPN` is the same order. If an order is missing an item
you can find (it has an active or reserve location) **and** an item you cannot
find, the unfindable item must not be split-cancelled until the findable one is
resolved. Those rows are listed under **Do NOT split cancel yet**. The check is
done against the whole file, so it also catches a findable item that sits at a
location you did not select.

### Filling in and printing an alt form

The **Alt form - EO pickup** section has two buttons above it:

- **Fill in alt form info** opens a popup for the details that are not on the
  OC Clearing export.
- **Print alt form** prints the finished form.

Both buttons are greyed out when there are no alt-form rows, and **Print alt
form** stays greyed out until the form has been filled in and saved.

The popup asks for a **Name** (shown at the top of the printed form), then one
entry per alt-form row, numbered 1, 2, 3, ... in the order they appear on the
page. Each entry has, in this order:

| Field | Source |
| --- | --- |
| SKU | Filled in from the `Item` column. Read-only. |
| Location | Typed by you. The `Reserve Locn` is deliberately *not* pre-filled, because a different location is sometimes picked. |
| Case | Typed by you (usually the last 5 digits of the case number, which is not on the OC Clearing export). |
| Qty | Filled in from the `Need` column. Read-only. |
| oLPN | Filled in from the `oLPN` column, last 4 digits. Read-only. |

The read-only fields are greyed out and cannot be edited. **Save** refuses to
close the popup until the name and every Location and Case are filled in. The
saved values are remembered while you print the form (so the same form can be
printed at several locations) and are only cleared when you click **Start
over**. The form prints portrait at 24px, one line per item, with columns sized
to their contents and the table centered on the page, and with the name and a
"Printed:" timestamp at the top and a "Thank you!" at the bottom.

### Printing

**Print sheet + barcodes** opens your browser's print dialog (choose a printer
or *Save as PDF*) with two parts, both landscape. The other two buttons print
just one part:

- **Print sheet** prints only the troubles table.
- **Print barcodes** prints only the barcode labels (no separate cover page).

The full **Print sheet + barcodes** output is:

- **The troubles table**, 10pt, limited to the columns `Tote Gid` through the
  first `Reserve Locn` (`Tote Gid`, `Label`, `Item`, `Need`, `Active Locn`,
  `Active Locn 2`, `Active OH`, `Reserve Locn`). Each column is only as wide as
  the widest text in it (header included), so the table does not stretch to the
  page edges, and the table is centered horizontally. `Need` cells above 1 are yellow, and the column header repeats on
  every printed page.
- **The barcode labels**, one block per printable tote with the label number
  above a Code 128 barcode and the tote number below, always as a single page
  at the end.

These three buttons print only the printable **Troubles** (and their barcodes).
The split-cancel, hold and duplicate sections are never printed. The **Alt
form** has its own dedicated print button (see above).

#### Splitting the list across pages

When a run is big enough that several people will go and get the items, use the
**Print pages** control just above the Troubles table:

- It starts at **1** page. A long list simply spills onto more printed pages at
  the same font size (nothing is shrunk).
- Use **+ / −** to split the list into 2, 3, … pages. The split starts out even
  (halves, thirds, …).
- Drag the handles on the left of the Troubles table up and down to move where
  each page begins. Each handle sits on its "Page N starts here" line; you can
  also focus a handle and press the up/down arrow keys.
- **Even split** resets the handles to an even division.

### Appearance

The page follows your browser/OS colour-scheme setting automatically by
default. A button in the top-right corner switches between **Auto**, **Light**
and **Dark**, and the choice is remembered on that computer. The printed
document is always light so it prints cleanly either way.

## What the output contains

The downloaded `.xlsx` has one sheet per section:

- **Troubles** - printable rows (active location present).
- **Alt Form** - no active location and a reserve location present, plus any
  rows added by hand from the preview.
- **Split Cancel** - no active or reserve location, order has nothing findable.
- **Split Cancel HOLD** - no active/reserve, but the order has a findable item.
- **Duplicates** - later exact copies of an earlier row (filled light red).
- **Barcodes** - one row per printable tote: the label number, the tote number,
  and a Code 128 barcode image.

Every data sheet also has:

- the new `Label` column immediately to the right of `Tote Gid`;
- `Need` cells greater than 1 filled yellow (fill `FFEB3B`);
- `Active OH` cells below 1 (zero or negative) filled orange (fill `FFE0B2`);
- a frozen header row.

## Decisions & assumptions

These are the choices the tool makes. They are all easy to change - see
"Customizing" below.

| Topic | Behaviour |
| --- | --- |
| Header detection | Finds the first row containing both `Tote Gid` and `Active Locn`, so the title rows at the top of the report are safe. |
| Filter column | The `Location` column (that is where `TRBL-PW-xx` appears). Matching ignores case and surrounding spaces. |
| Sort | First `Active Locn` column, descending (Z-A), case-insensitive. Blank values sort to the bottom. Ties keep their original order (stable). |
| Labels | Distinct tote values numbered `1, 2, 3, …` in the post-sort top-to-bottom order. Blank tote cells get a blank label. The same tote value always gets the same number. |
| Active location | The first `Active Locn` column being non-empty. |
| Reserve location | The first `Reserve Locn` column being non-empty. (`Reserve Locn 2` is only ever filled when the first is, so it is ignored.) |
| Sections | normal = active; alt = no active but reserve; split = neither; hold = split whose order has a findable item; duplicate = later exact copy. |
| Order grouping | Rows are grouped by `oLPN` across the whole file for the hold rule. |
| Duplicates | A row is a duplicate when its `oLPN`, `Tote Gid`, `Item`, `Need` and active location all match an earlier row. Other columns (e.g. `Time in OC`) may differ. The first occurrence keeps its section; later copies go to **Duplicates**. |
| Hidden rows | Rows can be hidden in any section. They stay visible but grey/struck on the page and are skipped when printing Troubles, barcode labels and the alt form (hidden alt rows are also left out of the fill-in popup). Labels and section counts are not recalculated, and the hidden state survives location-filter changes until **Start over**. |
| Manual alt rows | Any Troubles row can be added with **+alt**. It is hidden from the Troubles list/print and barcodes, and appears in the Alt form section, the alt-form popup, the printed alt form and the downloaded **Alt Form** sheet. Clicking **-alt** restores it to Troubles. Additions survive location-filter changes until **Start over**. |
| Low Active OH | A numeric `Active OH` below 1 (including 0 and negatives) marks that cell orange. Blank values are unknown and are not marked. This is only a marker; such rows are never moved to the alt form automatically. |
| Barcodes | Code 128, encoding the **tote number**, generated only for the printable **Troubles**. |
| Column toggle | Web tables default to `oLPN` through `Reserve Locn`, skipping `OC Mod`, `LPN Type` and `Reserve Locn 2`; the button reveals every column. The `.xlsx` always contains every column. |
| Preview length | Every row is rendered on the page, so the whole list is visible at once (no separate scroll box inside the table). |
| Print columns | Always `Tote Gid` … first `Reserve Locn`, landscape, 10pt, header repeated on every page. |
| Print pages | Splits the printable Troubles into pages for multiple pickers; the split is even by default and each page start can be dragged with the handle on the left of the table (or moved with the arrow keys). Barcodes stay on a single page at the end. |

If any of these should behave differently, it is a small change - see below.

## Customizing

All the spreadsheet logic lives in **`src/processor.js`**; the UI and the
workbook writing live in **`src/app.js`**.

- **Section rules:** `processData()` in `src/processor.js` (the `categories`
  mapping and the `orderHasFindable` map).
- **Need highlight colour:** search for `FFFFEB3B` / `#ffeb3b`.
- **Low Active OH highlight colour:** search for `FFFFE0B2` / `#ffe0b2`.
- **Duplicate colour:** search for `FFFFC7CE` (fill) and `FF9C0006` (font).
- **Barcode format / size:** `src/app.js`, the `makeBarcode()` /
  `makeBarcodeSvg()` functions. Change `format: 'CODE128'` to `'CODE39'`, etc.
- **Default web columns:** `visibleColumnIndices()` in `src/app.js`.
- **Printed columns:** the `PRINT_COLUMNS` array in `src/app.js`.
- **Alt form font size / layout:** `ALT_FORM_PRINT_CSS` in `src/app.js` (print)
  and the `.modal` / `.alt-field` rules in `src/styles.css` (popup). Both use
  24px at the moment.
- **Sheet names:** `buildWorkbook()` in `src/app.js`.

After editing, run `python3 build.py` to regenerate the single-file version.

## Privacy

The page reads the file locally with the File System APIs and writes the result
locally. There are no network calls, no analytics, and no backend. That is
deliberate, because the report contains order/OLPN/item data. Any hosting
option you choose in `HOSTING.md` keeps this property as long as you serve the
static files only.
